# Smart Counter (ต้นแบบ)

วางสินค้าหน้าเคาน์เตอร์ → CiRA CORE (DeepDetect) จับชนิดสินค้า → ส่งขึ้นเว็บ → เว็บแสดงตะกร้า ราคา ยอดรวม → สร้าง QR PromptPay → ยืนยันชำระเงิน → ตัดสต็อก

## รันเซิร์ฟเวอร์
```
pip install -r requirements.txt
python app.py          # เปิดที่ http://127.0.0.1:5000
python test_flow.py    # (ไม่บังคับ) ทดสอบตรรกะหลัก
```
- ค่าที่ปรับได้ด้วยตัวแปรสภาพแวดล้อม: `PROMPTPAY_ID` (เบอร์ PromptPay, ค่าเริ่มต้น 0612656498), `PENDING_TTL` (วินาทีที่ออเดอร์ค้างรอจ่าย, ค่าเริ่มต้น 300)
- ถ้าอยากเริ่มฐานข้อมูลใหม่ ให้ลบไฟล์ `smart_counter.db`

## ต่อกับ CiRA CORE
1. flow: `Button Run → WebCam/VideoFile → DeepDetect → Python+ → Debug`
2. วางโค้ดจาก `cira_python_plus.py` ในกล่อง Python+ (ต้องมีแพ็กเกจ `requests`)
3. ถ้าเซิร์ฟเวอร์อยู่คนละเครื่อง แก้ `SERVER` เป็น IP ของเครื่องนั้น
4. ชื่อคลาสของโมเดลต้องตรงกับรหัสสินค้าในตาราง `PRODUCTS` ใน `app.py` (ตอนนี้ตรงทั้ง 4 ชื่อ)

## ราคาและสต็อกเริ่มต้น
ราคา (199 / 159 / 189 / 49 บาท) และสต็อก (20 ชิ้น) ใน `PRODUCTS` เป็น **ค่าสมมติ** แก้ได้ที่ไฟล์ `app.py` ก่อนรันครั้งแรก หรือปรับสต็อกในหน้า "สต็อก" ได้ตลอด (ราคาแก้ที่ `app.py` แล้วลบ `smart_counter.db`)

## วิธีทำงานของสต็อกและการชำระเงิน
| เหตุการณ์ | สถานะออเดอร์ | สต็อก |
|---|---|---|
| กด "ชำระเงิน" (สร้าง QR) | pending | **จอง** (พร้อมขาย = คงเหลือ − จอง) |
| กด "ยืนยันว่าชำระเงินแล้ว" | paid | **ตัดจริง** |
| กด "ยกเลิก" หรือหมดเวลา | cancelled / expired | คืนที่จอง |

- ไม่ได้เชื่อมธนาคาร จึง **ตรวจเงินเข้าอัตโนมัติไม่ได้** ใช้ปุ่มยืนยันแทน (จำลองการที่พนักงานเห็นเงินเข้า) การตรวจจริงต้องใช้ API ของธนาคาร บริการตรวจสลิป หรือ payment gateway
- การจองใช้คำสั่ง SQL แบบมีเงื่อนไขภายใน transaction จึงขายเกินสต็อกไม่ได้ แม้กดพร้อมกัน
- QR สร้างตามมาตรฐาน EMV/PromptPay (ผู้รับเป็นเบอร์โทร, ระบุยอด, สกุลเงิน THB) ก่อนใช้โชว์จริงควรลองสแกนด้วยแอปธนาคารของตัวเองสักครั้ง

## ข้อจำกัดที่ควรเขียนในรายงาน
- ผลตรวจจับเปลี่ยนทุกเฟรม จึงใช้ปุ่ม "สแกน" ล็อกรายการ ณ ขณะนั้น
- วางสินค้าแยกกัน ไม่ซ้อนทับ ไม่งั้นนับขาด
- มีเคาน์เตอร์เดียว ตะกร้าเดียว (ยังไม่แยกลูกค้า)
- ไม่มีระบบล็อกอิน ใช้ในเครือข่ายภายในเท่านั้น
